# 演示脚本与彩排手册

> 原则：**功能优先**。演示的第一目标是「不出事故地把功能展示完」，
> 第二目标才是秀性能数字。所以本手册里每一段都配了**故障应急**。

---

## 0. 两种演示形态（现场按条件选）

| 形态 | 需要什么 | 说明 |
| :-- | :-- | :-- |
| **A 真机** | 板卡 + 摄像头 + LED + 上位机 | 主形态 |
| **B 无硬件彩排** | 只要一台电脑 | 用 `host/vision_console.py --demo` 或 `--file` 回放；**答辩前一定排练一次**，这是防翻车的最后一道保险 |

## 1. 演示前 30 分钟准备

1. **接线**：摄像头排线（方向别插反）、LED、串口线；按 `doc/硬件资源与引脚.md` 的检查清单过一遍。
2. **上电顺序**：先接好所有线 → 再上电 → 观察 `led_ok` 5 秒内点亮。
3. **上位机**：

   ```powershell
   py vision\host\vision_console.py --list          # 先确认串口号
   py vision\host\vision_console.py --port COM3     # 真机
   py vision\host\vision_console.py --demo          # 无硬件的兜底演示
   ```

4. **彩排脚本**（照下面第 3 节走两遍，一遍计时）。
5. **备份**：把演示视频、`--demo` 终端录屏、`--file` 用的日志文件都拷到演示机上。

## 2. 现场演示流程（10 分钟版）

| 时间 | 动作 | 解说要点 |
| :-- | :-- | :-- |
| 0:00 | 上电，指屏幕 | 「FPGA 上电后自动跑：先配摄像头（SCCB 29 条寄存器），再出结果，不需要人工干预」 |
| 0:30 | 放上 **A 类**物品 | 「大块 → A 类，外接框、置信度、延迟、计数都在这块屏上」 |
| 1:30 | 拿走 → 再放 **B 类** | 「物品拿走灯全灭；换上细长件判 B 类，**计数只在物品出现时 +1**」 |
| 2:30 | 放上 **C 类** | 「小块判 C 类」 |
| 3:00 | 拿开放回同一件 | 「同一件反复放，计数每次 +1；连续放 20 次不丢」 |
| 4:00 | 指延迟与帧率两项 | 「识别延迟 X µs，帧周期 33 ms，延迟占一帧的 Y%」 |
| 5:00 | 拔掉摄像头再插回 | 「相机看门狗发现连续等不到结果，自动重启相机并重配，自己恢复」（M5 稳定性） |
| 6:00 | 讲架构图 | 「**图像数据不进 CPU、不进 Cache**：帧内统计和分类都在视觉模块里做完，CPU 只读结果寄存器 —— 一举解决 Cache 一致性和总线带宽两个问题」 |
| 7:30 | 讲 AI 加速 | 「分类器是**可替换件**：现在是阈值+形状规则；AI 阶段换成 int8 定点小 CNN，接口不变。现网是加宽加深版 LiteNet-3（48,96,144,192,144，10 层），100 类 CIFAR-100 灰度 int8 量化识别率 **42.84%**（浮点 44.20%，纯量化损失 1.36pp），LUT 只占 ~4%、BRAM 全空，换结构/换权重不用改 RTL」（见 `doc/AI加速多方案比较与推荐实施方案.md` 与 `tools/README.md`） |
| 8:30 | 讲资源 | 「视觉侧 LUT 用量 X，整机 `CoreMark/LUTs` = …」 |

**5 分钟版**：只做 0:00 / 0:30 / 1:30 / 5:00 / 6:00 五段。

## 4. 故障应急表（贴在演示桌上）

| 现象 | 最可能原因 | 30 秒处置 |
| :-- | :-- | :-- |
| 屏幕一直「等待 FPGA 上报结果」 | 串口没开/波特率不对/线接反 | 换 `--demo` 先撑住场面；同时查 COM 口与 TX↔RX |
| 有数据但类别永远是 `--` | 物品没进 ROI，或现场光变导致阈值失效 | 放慢动作把物品放正；必要时调 `THRESH`（寄存器可写） |
| 框位置抖动/乱跳 | 反光或背景不平 | 换哑光背景侧、关顶灯直射 |
| 拔插摄像头后不出结果 | 相机自恢复还没走完（约 30 ms 后开始重配） | 等 2 秒；仍不出就断电重启 |
| 完全没输出、灯也不亮 | 没配好程序/引脚不对 | 切 `--demo` 演示软件部分，硬件留到答疑 |
| 评委要求看波形 | — | 打开 PDS 的 ILA 工程，抓 `frame_new` 触发（见 `pds/README.md` §5） |

## 5. 验收清单（彩排时逐条打勾）

- [ ] 上电自动进入工作状态，不需要手动按复位
- [ ] 物品放入检测区，框位置稳定不抖
- [ ] A/B/C 三类灯正确，屏幕上类别/框/延迟/计数四项都在刷新
- [ ] 依次放上/拿起 20 次，计数正确、不重复计数、不卡死
- [ ] 拿走后灯全灭、计数不增加
- [ ] 断电重启后自动恢复
- [ ] 相机拔插后能自动恢复
- [ ] 录一段 3 分钟以内的演示视频存好
- [ ] `--demo` 兜底路径演练过一次

## 6. 评委可能追问的问题（准备答案）

| 问题 | 回答要点 |
| :-- | :-- |
| 为什么图像不走 CPU？ | 帧内统计/分类在视觉模块内部完成，CPU 只读结果寄存器。省总线带宽、免 Cache 一致性维护，CPU 侧唯一改动是「一个地址区间比较器」。 |
| 跨时钟域怎么处理的？ | 三个跨域点全部「翻转握手 + 打两拍」，数据在 toggle 之前已稳定远超两拍；时序约束里两个时钟声明为异步组。 |
| AI 加速为什么不做大？ | 帧率 30 fps，33 ms 预算；推理只要 <1 ms 就足够，所以瓶颈是面积而不是吞吐。而 `CoreMark/LUTs` 是评分项，所以选「少 MAC + 时间复用」。 |
| 识别率怎么测的？ | 现场连放 20~30 次记录成功次数；训练阶段另有验证集准确率（float 与 int8 各一份）。 |
| 和 CPU 组怎么分工？ | 总线从端接口往后全部是视觉子系统；CPU 侧只需保证地址译码 + 不可缓存属性 + 一个中断号（详见 `doc/接口契约.md`）。 |
