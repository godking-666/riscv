# 视觉子系统 接口契约 v1.0

> 状态：**草案，待与 CPU 组评审**
> 对应实现：`rtl/vision_top.v`、`rtl/vision_regs.v`、`sw/vision_regs.h`
> 变更规则：任何一方改动本契约，必须双方确认并递增版本号。

---

## 1. 角色边界

| 归属 | 内容 |
| :-- | :-- |
| **CPU 组** | CPU 核、流水线、转发/阻塞、Cache、总线主机、**地址译码**、中断控制器、CSR、工具链 BSP |
| **视觉组（本契约）** | 摄像头采集、帧内统计、物品分类（AI 加速器）、MMIO 寄存器从端、指示灯、驱动与应用、显示上报 |

分界线就是**一条总线从端接口**。只要下面这份接口冻结，两边可以完全并行开发；视觉侧已用一个总线 BFM 替代 CPU 跑通端到端仿真（见 `sim/vision_tb.v`）。

---

## 2. 总线从端时序

风格与工程既有 `inst_rom` / `data_ram` 保持一致，**不引入新协议、不引入 wait state**。

| 信号 | 方向 | 位宽 | 说明 |
| :-- | :-- | :-- | :-- |
| `bus_sel` | in | 1 | 片选。由 CPU 侧地址译码产生，本模块不解码高位 |
| `bus_we` | in | 1 | 1=写，0=读 |
| `bus_addr` | in | 32 | 字节地址。本模块只用 `[11:0]` |
| `bus_wdata` | in | 32 | 写数据 |
| `bus_be` | in | 4 | 字节使能。**当前实现为 32 位整字访问，字节使能未使用**，请按整字访问 |
| `bus_rdata` | out | 32 | 读数据，**寄存输出，1 拍延迟**（同 `data_ram`） |
| `irq` | out | 1 | 电平中断，= `IRQ_EN && DONE` |

- **写**：`bus_sel && bus_we` 在 `posedge clk` 采到即提交。
- **读**：`bus_sel && !bus_we` 在 `posedge clk` 采到，**下一拍** `bus_rdata` 有效。
- **对 CPU 的性能影响**：从端永远不拉低就绪、不插入等待周期，因此不会拖累 CoreMark 与主频。只有在软件主动读写视觉寄存器时才会占用总线。

## 3. 地址映射

统一 32 位地址空间。视觉段：

| 区域 | 起址 | 大小 | 属性 |
| :-- | :-- | :-- | :-- |
| 视觉 MMIO | `0x8000_0000` | 4 KB | **必须不可缓存** |

选 `0x8000_0000` 的理由：最高位为 1，CPU 侧地址译码只需判一根线，和低地址段的 ROM/RAM 天然隔开。

> 现状提醒：当前 `mycpu_sync.v` 里 `inst_rom` 与 `data_ram` 都从低地址译码（各自 `[11:2]`），**还没有 MMIO 段**。本契约落地需要 CPU 侧新增地址译码：低地址走 ROM/RAM，`0x8000_0000` 段拉高 `bus_sel` 给视觉模块。

### 3.1 Cache 属性（★ 最重要的一条）

CPU 组已确定要做到 Cache 模块，因此这一条必须在 Cache 设计里一并落实：

1. **`0x8000_0000` 起的 4KB 必须不可缓存、直通访问。**
   若被 D-Cache 缓存：
   - 读 `STATUS.DONE` 会一直读到旧值 → 软件永远等不到结果；
   - 写 `CTRL` 可能只落在 Cache 里不下发 → 使能、CFG_COMMIT 全部失效。
   - 推荐做法：D-Cache 的命中判定里直接排除该地址段（区间比较，一个比较器即可），比做属性表或页表都省。**注意指令 Cache 不受影响**，这里只涉及 D-Cache。
2. **该段写必须有序。** 软件会先写 `ROI_*`、再写 `CTRL`（CFG_COMMIT）。
   推荐：该段写直通、不进写缓冲。这样软件天然有序，**CPU 侧不需要额外的 fence 指令**，省掉一条 CSR/ISA 改动。
3. **图像数据全程不进 CPU、不进 Cache。** 帧内统计在视觉模块内部完成，CPU 只通过 MMIO 读结果寄存器。
   这一条同时解决两个问题：不需要 Cache flush/invalidate，不需要 DMA 一致性协议，也不需要让 CPU 碰像素数据。请 CPU 组**不要**为视觉功能增加任何 Cache 维护指令。

**结论**：Cache 侧的额外工作量 = 一个地址区间比较器。这是本契约里唯一需要改 CPU 内部逻辑的地方。

## 4. 寄存器表

片内偏移 = `bus_addr[11:0]`。完整定义见 `sw/vision_regs.h`，两者必须同步。

| 偏移 | 名称 | 访问 | 复位默认 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| `0x000` | ID | RO | `0x56495331` | 魔数 "VIS1"，软件用它探测器件是否在位 |
| `0x004` | VERSION | RO | `0x0001_0000` | 主版本.次版本 |
| `0x008` | CTRL | RW | 0 | b0 EN 使能；b1 SOFT_RST 自清；b2 IRQ_EN；b3 CFG_COMMIT 自清 |
| `0x00C` | STATUS | RO | 0 | b0 EN；b1 DONE；b2 ERR；b3 CAM_OK(粘滞) |
| `0x010` | IRQ_CLR | WO | — | 写任意值清 DONE |
| `0x014` | FRAME_CNT | RO | 0 | 已接收帧数 |
| `0x018` | ITEM_CNT | RO | 0 | 累计检出物品数，**只在"物品出现"沿自增**，不随帧累加 |
| `0x01C` | FRAME_CYC | RO | 0 | 帧周期，单位 cam 时钟周期 |
| `0x020` | ROI_X | RW | 0 | 物品检测区左上角 X |
| `0x024` | ROI_Y | RW | 0 | 物品检测区左上角 Y |
| `0x028` | ROI_W | RW | 320 | 物品检测区宽 |
| `0x02C` | ROI_H | RW | 240 | 物品检测区高 |
| `0x030` | THRESH | RW | 128 | `[7:0]` 阈值；`[8]` 极性（0=比阈值暗算前景） |
| `0x034` | MIN_PIX | RW | 64 | 小于该前景像素数视为"无物品" |
| `0x038` | AREA_C_MAX | RW | 500 | 前景像素数小于该值判为 C 类 |
| `0x03C` | CLASS | RO | 255 | 0=A 1=B 2=C 255=无物品 |
| `0x040` | SCORE | RO | 0 | 置信度，千分比（前景像素数 / ROI 面积 × 1000） |
| `0x044` | BOX_X0 | RO | 0 | 外接框左 |
| `0x048` | BOX_Y0 | RO | 0 | 外接框上 |
| `0x04C` | BOX_X1 | RO | 0 | 外接框右 |
| `0x050` | BOX_Y1 | RO | 0 | 外接框下 |
| `0x054` | FG_CNT | RO | 0 | 前景像素数 |
| `0x058` | OBJ_W | RO | 0 | 目标宽 |
| `0x05C` | OBJ_H | RO | 0 | 目标高 |

### 4.1 软件使用顺序（重要）

```
1. CTRL.EN = 0                     // 先停，避免配置改到一半被采到
2. 写 ROI_X/Y/W/H、THRESH、MIN_PIX、AREA_C_MAX
3. CTRL = CFG_COMMIT               // 把上面这批配置一次性推给 cam 时钟域
4. CTRL.SOFT_RST                   // 清计数与 DONE/ERR
5. CTRL.EN = 1                     // 开始出结果
6. 循环：写 IRQ_CLR 清 DONE -> 等 STATUS.DONE -> 读 CLASS/SCORE/BOX_*/FG_CNT/...
```

**`CFG_COMMIT` 这一步不能省。** ROI 等配置跨到摄像头时钟域，必须靠一次显式提交把所有值同时推过去；否则配置改到一半可能被某一帧采到，产生一帧错误结果。

## 5. 中断

- 1 根 `irq`，电平型，`= IRQ_EN && DONE`。
- 软件清中断：写 `IRQ_CLR`。
- 需要 CPU 组分配：**一个中断号**，以及中断控制器里的一路输入。
- **功能优先建议**：先用轮询 `STATUS.DONE`（当前驱动 `vision_wait_done()` 就是轮询版），中断等 CPU 侧中断控制器稳定后再接。这样两边解耦，不互相卡进度。

---

## 6. 时钟与复位

| 时钟域 | 频率（参考） | 内容 |
| :-- | :-- | :-- |
| `clk` | CPU 主时钟，93.75 MHz（= CPU 组 `core_clk`，见 SoC 结构图 2026-10-05） | MMIO 寄存器、分类器、指示灯 |
| `cam_pclk` | 摄像头 PIXCLK | DVP 接收、帧内统计 |

- `rstn` 为低有效；cam 域复位在 `vision_top` 内部用「异步复位、同步释放」同步过去，**CPU 组只需要给一根 `rstn`**。
- 两处跨时钟域均用「翻转握手 + 多拍稳定」：配置 clk→cam（`cfg_toggle`），结果 cam→clk（`res_toggle`）。
- **视觉侧不会给 CPU 侧引入任何新的时钟域要求。**

## 7. 模块端口冻结版

CPU 组例化用这个端口表（对应 `rtl/vision_top.v`）：

```verilog
module vision_top (
    input  wire        clk,          // CPU 主时钟
    input  wire        rstn,         // 低有效复位

    // 摄像头 DVP
    input  wire        cam_pclk,     // 摄像头 PIXCLK
    input  wire        cam_vsync,
    input  wire        cam_href,
    input  wire [7:0]  cam_data,

    // MMIO 从端（接 CPU 地址译码出来的片选）
    input  wire        bus_sel,
    input  wire        bus_we,
    input  wire [31:0] bus_addr,
    input  wire [31:0] bus_wdata,
    input  wire [3:0]  bus_be,
    output wire [31:0] bus_rdata,

    // 中断
    output wire        irq,

    // A/B/C 指示灯
    output wire        led_a,
    output wire        led_b,
    output wire        led_c
);
```

## 9. AI 加速单元（CNN）接口 —— 追加约定

> 方案全文见 `doc/AI加速多方案比较与推荐实施方案.md`。本节只写「与外部有关」的那几条。
> 结论：**对 CPU 组、对软件，全部是追加，没有一处需要改现有约定。**

### 9.1 替换点（与现有分类器同端口）

`rtl/vision_cnn_top.v` 的端口与 `rtl/vision_classifier.v` **完全一致**：

```verilog
    input  wire        frame_new,
    input  wire [31:0] fg_cnt, box_x0, box_y0, box_x1, box_y1,
    input  wire [31:0] roi_w, roi_h, min_pix, area_c_max,
    output reg  [31:0] cls, score, obj_w, obj_h,
    output reg         valid, done
```

`vision_top` 用参数二选一：

```verilog
parameter USE_CNN = 0;   // 0 = 规则分类器（默认，保底）; 1 = CNN 加速器
```

- `USE_CNN=0` 时综合出来的电路与现在**完全一样**，零风险。
- 两个模块下游相同，`rtl/vision_regs.v` 一行都不用改。

### 9.2 图像通路（只在视觉子系统内部，不经总线）

CNN 需要像素，但**仍然不进 CPU、不进 Cache**：

```
cam_pclk 域：ROI 裁剪 + 盒式降采样 32x32 + 减均值  ->  写双口 BRAM
                                                       |
                                                       v 写完一帧翻转 pix_toggle
clk 域：打两拍取边沿 -> 启动推理 -> 直接写 cls/score
```

- 双口 BRAM 由 `rtl/viz_pix_buf.v` 实现；CPU 侧完全不可见。
- 跨域只用「翻转握手 + 多拍稳定」，与既有的 `cfg_toggle` / `res_toggle` 同一套做法。
- 不引入第三个时钟域，`pds/timings.sdc` 里加两条异步声明即可。

### 9.3 新增的只读寄存器（追加，不改动现有偏移）

| 偏移 | 名称 | 访问 | 说明 |
| :-- | :-- | :-- | :-- |
| `0x060` | AI_CYCLES | RO | 上一次推理耗费的 `clk` 周期数（写进分析报告，佐证延迟） |
| `0x064` | AI_CONF | RO | 类别置信度 0~1000（与 SCORE 同义，便于两版分类器对比） |
| `0x068` | AI_STATUS | RO | b0 模型就绪；b1 推理中；b2 量化饱和 |

**落地时机**：C1 阶段实现 CNN 时同步追加到 `rtl/vision_regs.v` 与 `sw/vision_regs.h`（两处必须同改）。
在此之前编译器综合出来的地址空间不含这三个寄存器，**对 CPU 组零影响**。

### 9.4 对 CPU 组的净影响

1. 地址空间、片选、不可缓存属性：**不变**。
2. 不需要 Cache 维护指令、不需要 DMA、不需要新的总线主端。
3. 中断：仍是既有的 1 根 `irq`，不新增。
4. 唯一要留意的：若 CPU 侧 LUT/DSP 紧张，AI 单元占用需要一起算进 `CoreMark/LUTs`；
   预算见方案 §4.8（≤8k LUT / ≤16 DSP / ≤8 BRAM18），且可用 `USE_CNN=0` 完全关掉。
