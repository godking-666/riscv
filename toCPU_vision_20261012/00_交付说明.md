# vision 侧交付给 CPU 组（整包上板）说明

> 更新：2026-10-12 · 板卡：**盘古100K MINI（MES2L676-100HP-MINI, PG2L100H-6IFBG676）**
> 接口契约 **v1.0（草案，待 CPU 组评审确认）**；vision 侧红线：图像数据不进 CPU/Cache，接口只增不改。

---

## 0. 一句话状态

vision 侧已为**新板卡**完成全部适配：FBG676 工程跑通、IO_LOC 物理引脚全绑定、27MHz 晶振直驱定案、**正式 bit 流已生成**（demo 自包含版，可先烧录验证摄像头+识别通路）。整包集成需要 CPU 组做 4 件事（见 §3）。

> **关键澄清（UART 归属）**：正式整包方案里，**结果行由 CPU 软件发出**——`vision_top` 没有 UART 端口，`sw/main.c` 通过 CPU 组 BSP 的 `uart_putc()` 打印结果行协议。demo 版才有硬件串口（uart_txd=C24，直出结果行，不依赖 CPU），用于单独验证通路。

## 2. 板卡/时钟速查（队友必读）

- **系统时钟**：新板仅 27MHz 单端晶振（FPGA_GCLK_27M = **D18**）。demo 版**直驱 27MHz**（UART 误差 +0.16%、SCCB +0.75%，容差内）。
- **整包时钟**：若 SoC 用 PLL 倍频（候选 108MHz = 27×4），core_clk 由 CPU 组定；**例化 vision_top 时必须按实际时钟传 `CAM_CLK_HZ` 参数**（决定 SCCB/UART 分频，写错 = 上板串口乱码）。
- **DDR3 用的 125MHz 差分晶振（N3/N2）不能当系统时钟用**，仅供 DDR3 控制器。
- **UART**：demo 版 uart_txd=C24（CP2102，115200-8N1，硬件直出结果行）；整包版 UART 由 CPU 组自己的外设实现（软件 uart_putc 发出），引脚归 SoC 顶层管。
- **按键**：5 个低有效（KEY0=C22 … KEY4=B20）；demo 用 KEY0 作复位。
- **LED**：高电平亮，LED0=A20 LED1=C19 LED2=C18 LED3=E18 LED4=A17；**vision_top 只有 led_a/b/c 三个分类指示**（A/B/C 类），整包接前 3 个即可；LED5-7 手册未列，待原理图核对。
- **摄像头**：双目 OV5640 模组（J17 排针）→ J10 扩展口 pin-pin 直插；J17 脚 37/38=GND、**39/40=A3V3（供电）**；模组自带 24MHz 晶振，不需要 FPGA 给 XCLK。**cam_pwdn 输出悬空即可**（模组 J17 无 PWDN 脚，demo 未绑）。
- **图像数据不进 CPU/Cache**：像素只在 vision 内部走，CPU 只读结果寄存器（0x8000_0000 起 4KB，**必须不可缓存**）。

## 2.1 vision_top 端口与参数速查（队友例化用）

**端口**（例化时逐一对齐）：

| 端口 | 方向 | 位宽 | 说明 |
| :-- | :-- | :-- | :-- |
| clk / rstn | in | 1/1 | 系统时钟（按 core_clk）/ 低有效复位 |
| cam_pclk / cam_vsync / cam_href | in | 1/1/1 | 摄像头 DVP 时序 |
| cam_data | in | 8 | DVP 像素 |
| cam_sda | inout | 1 | SCCB 数据（开漏，内部拉低/释放） |
| cam_scl | out | 1 | SCCB 时钟 |
| cam_pwdn | out | 1 | **模组无此脚，悬空即可**（demo 未绑） |
| cam_reset_n | out | 1 | 摄像头复位（低有效，接模组 REST=T22） |
| bus_sel / bus_we | in | 1/1 | 片选（0x8000_0000 段译码）/ 写使能 |
| bus_addr / bus_wdata | in | 32/32 | 字节地址（只用 [11:0]）/ 写数据 |
| bus_be | in | 4 | 字节使能（当前实现按整字访问，未用） |
| bus_rdata | out | 32 | 读数据（寄存器输出，**1 拍后有效**） |
| irq | out | 1 | 电平中断（IRQ_EN && DONE） |
| led_a / led_b / led_c | out | 1/1/1 | A/B/C 类指示（高电平亮） |

**参数**（例化时按实际时钟传，**默认值是旧板 93.75MHz 假设，整包务必重设**）：

| 参数 | 默认 | 整包建议 | 说明 |
| :-- | :-- | :-- | :-- |
| `CAM_CLK_HZ` | 93750000 | **按实际 core_clk** | 决定 SCCB/UART 分频（demo=27MHz 已验证）；**传错 = 串口乱码/摄像头配不上** |
| `CAM_SCL_HZ` | 100000 | 100000 | SCCB 时钟 |
| `CAM_PWDN_SETTLE_MS` | 10 | 10 | 上电等待 |
| `CAM_RESET_SETTLE_MS` | 20 | 20 | 复位释放后等待 |
| `BYTES_PER_PIX` | 2 | 2 | RGB565 |

> 另注意：`sw/main.c` 里 `#define CAM_CLK_HZ 24000000u` 是**摄像头 PCLK**（延迟 us 换算用，非系统时钟），按实际 OV5640 配置填。

## 3. CPU 组要做的 4 件事

1. **例化 + 接线**：SoC 顶层例化 `vision_top`（端口/参数见 §2.1），接总线从机端口（bus_sel/we/addr/wdata/be/rdata/irq，时序同 inst_rom/data_ram，无 wait state）。
2. **地址译码**：`0x8000_0000` 段拉高 `bus_sel`（最高位判一线即可），低地址段仍走 ROM/RAM。
3. **D-Cache 排除**：`0x8000_0000–0x8000_0FFF` 不可缓存、直通访问（一个区间比较器即可）；写必须有序（软件先写 ROI_* 再写 CTRL，无需额外 fence）。
4. **时钟与引脚**：按定的 core_clk 例化（**传对 CAM_CLK_HZ**）；把 vision 侧端口（clk、cam 全路、led_a/b/c）合并进整包 IO_LOC，参考 `vision.fdc` 的端口→引脚映射（注意 demo 的 uart_txd/led_run 等是 demo 顶层端口，整包不接）。

> 软件侧：把 `sw/` 三个文件编进工程，main.c 依赖 `uart_putc()`（BSP 提供）。探测 ID=0x56495331 → 写 ROI/CTRL → 等 DONE → 读 CLASS/BOX → 结果行经 uart_putc 发出。

## 4. 上板验证路径（建议顺序）

1. **先烧 demo bit 流**（`vision_demo_top.sbit`）：验证 27MHz 时钟、摄像头采集、分类、UART 结果行——**不依赖 CPU**，能独立定位问题。
2. **再整包集成**：CPU 组合流后烧整包 bit 流，跑 `sw/main.c`（探测 ID=0x56495331 → 写 ROI/CTRL → 等 DONE → 读 CLASS/BOX → 收 UART 结果行）。
3. 现场演示按 `doc/演示脚本.md` 走。

## 5. 注意/风险

- **接口只增不改**（契约 v1.0）：队友如需新寄存器/端口，走追加 + 契约升版，双方确认。
- **类别编码唯一**：0=A 1=B 2=C 255=无物品；结果行协议 `VISION,<帧号>,<类别>,<x0>,<y0>,<x1>,<y1>,<置信度>,<延迟us>,<计数>\n`（三处一致：main.c / vision_report.v / vision_console.py）。
- demo bit 流是 **wider3 最终 AI 版**（int8 42.84%），与整包共用同一份权重 ROM。
- 队友若改板卡（如用 J25 扩展口而非 J10），引脚映射须按 `doc/硬件资源与引脚.md` 重核对。
